Introduction

This document describes changes made in the development version of the RTPProxy since the latest stable release, RTPProxy 3.2.0 (March 2026). These changes are not part of any release yet.

Release notes for the stable releases are available on the GitHub releases page.

New Features

RTP Flood Mitigation

Two new command-line options and two matching per-stream session parameters allow mitigating the effects of RTP floods (reported by Sandro Gauci):

  • --maxpps=rtp_pps[,rtcp_pps] and the S pps=rtp_pps[,rtcp_pps] session parameter set the maximum allowed rate of incoming packets per second. Packets exceeding that rate are dropped early in the processing.

  • --maxpsize=rtp_mps[,rtcp_mps] and the S mps=rtp_mps[,rtcp_mps] session parameter set the maximum allowed size of incoming packets. Packets exceeding that size are discarded the same way.

Packet Port API for Embedding Applications

Applications embedding the RTPProxy library can now plug into its packet handling pipeline directly via shared memory packet rings (rtpp_packetport, built on the bundled libRTQueue), instead of exchanging packets over sockets. A packet port is used as the remote target of a session in the special RTQ:0xpointer port_tag format, and the flushing policy of its outbound queue can be set when it is created. This API is a work in progress.

Inherited Control Socket

The fd:N control socket, so far only available to applications embedding the RTPProxy library, can now be used with -s in the standalone rtpproxy as well. The rtpproxy then uses socket N inherited from the parent process instead of creating one, and determines its type from the socket itself: a datagram socket is used as udp: / udp6:, a listening stream socket as tcp: / tcp6: / cunix:, and a connected stream socket as a single control channel. This allows e.g. a supervisor or a test framework to create the control socket on an ephemeral port and pass it to the rtpproxy.

acct_csv: logfile Parameter

The location of the CSV file written by the acct_csv module can now be set with the new logfile parameter. Since the parameter is optional, the module can still be loaded with the --dso command-line option.

ICE-Lite: Peer-Reflexive Candidates

The ice_lite module now adds the remote candidate as a peer-reflexive one when it receives a STUN request from an unknown candidate, instead of dropping the request.

extractaudio

  • 16 kHz output (-r 16000). G.722 is decoded at its native rate and narrowband codecs are upsampled, so that legs using different codecs stay aligned in one file.

  • Encoder options: Opus bitrate (-b) and compression level (-C).

  • Support for the AES-192/256-CM and AES-GCM SRTP crypto suites, in addition to AES-128-CM.

  • SRTP decryption now also works for recordings in the native RTPProxy format, not just for pcap recordings.

Fixed Bugs

  • The rtpproxy crashed instead of exiting with an error when the configuration of a module was rejected, e.g. because of an unknown or invalid parameter.

  • make install put the packet port headers of the librtpproxy into include/src/librtpproxy instead of include/librtpproxy.

Performance Improvements

  • Sockets cache their session and stream, skipping the hash table lookup for the second and subsequent packets.

  • The sender of a stream is obtained via a weak reference, and locking in the packet receive path has been reduced.

  • Atomic operations have been relaxed where strict ordering is not needed.

Documentation

  • New manual pages for extractaudio(1) and makeann(1).

  • The user manual has been updated.

Build and Testing

  • Fixed the build with the latest compilers on Ubuntu 24.04.

  • Production (non-debug) binaries are now built with NDEBUG defined.

  • Fixed issues reported by CodeQL: alloca() calls in loops, and possible integer overflows in extractaudio and in the udp_contention performance tool.

  • The RPTL test scripting language can now run external commands, start rtpproxy instances with any type of control socket, expose their control addresses and PIDs to the script, and loop over lists of values. The recording, session timeout, forwarding and playback tests have been rewritten using it, so they no longer need any pre-determined ports and can run in parallel. The forwarding and playback tests no longer need root privileges, and the playback test runs all of its playbacks at once. As a result, the functional test suite now completes more than twice as fast.

  • The test suite can be run as root, with the rtpproxy and the tools dropping privileges to a dedicated user.

  • The CI builds now cover Ubuntu 26.04 and use bcg729 1.1.2.
